## 2주차 미션6 3팀 위키

#### 1. Docker를 사용하는 이유가 뭘까요?
- 환경 재현 가능: 로컬에서 만든 환경을 다른 컴퓨터에서도 그대로 실행하기 위해서다. mac환경에서 작업한 산출물도 ubuntu(EC2) 환경에서 정상적으로 동작 가능하며, '내 컴퓨터에서는 되는데요?' 에 대한 문제를 원천 차단한다.
- 배포 단순화: 서버에 배포 환경을 직접 구현할 필요 없이, docker pull과 docker run으로 배포가 완료된다.
- 복구 용이성: 서버 장애시 새 인스턴스에서 이미지를 pull해서 서비스 복구가 가능하다.

#### 2. 어떤 점은 더 불편한가요?
- 수정 사이클 번거로움: 작은 변경에도 build -> push -> 기존 컨테이너 삭제 -> run의 작업을 해야한다.
- 이미지 용량 제한: 이미지가 커지면 S3 등의 외부 저장소를 사용해야 한다. 
- 디버깅 계층 증가: 문제 발생시 서버, 네트워크, 컨테이너, 이미지 중 어디가 문제인지 구분해야 되서 디버깅이 어려워진다.


#### 3. 이번 미션에서는 하나의 EC2에 하나의 Docker container를 배포했습니다. 만약에 여러대의 EC2에 여러 개의 컨테이너를 배포해야 한다면 어떻게 해야 할까요?
- 이번 미션에서 한 방식은 수동 방식으로 (SSH접속 -> pull ->run)을 N대로 확장배포 하면 이 과정을 모두 사람이 반복해야 한다. 더더구나 특정 서버의 컨테이너가 죽어도 감시할 방법이 없어서 힘들다.
- 그 대안으로 쿠버네틱스와 같은 orchestrator 도구를 사용할 수 있다. "이 이미지를 컨테이너 N개를 유지해라"라고 선언하기만 하면 컨테이너의 서버 배치, health check, 무중단 버전 교체, 로드 밸런싱을 자동으로 수행한다.
